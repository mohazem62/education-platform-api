# المسارات المالية

راتب المعلم = مجموع `TeacherRateSnapshot` للجلسات مؤكدة الحضور. يولد النظام Payout وPayoutItems فريدة حسب الجلسة. الانتقالات المسموحة: `Draft → PendingReview → Approved → Paid`، مع مسار اعتراض يعيد للمراجعة؛ لا يمكن للمعلم إرسال قيمة راتب حاكمة.

عند إغلاق الفترة: تُقرأ الدفعات المدفوعة والمصروفات المعتمدة ورواتب المعلمين المعتمدة/المدفوعة، ويحسب `NetProfit = Revenue - TeacherCosts - Expenses`. تُراجع نسب الشركاء الفعالة (100%)، ثم تحفظ النسب وصافي الربح كم snapshots داخل PartnerDividend، وتُنشأ القيود وتغلق الفترة كلها في transaction واحدة. الإعادة idempotent، والسجلات المالية لا تُحذف.

قواعد الاعتراف الحالية مذكورة في `ASSUMPTIONS.md` ومحصورة داخل خدمة المالية لتغييرها لاحقًا.
