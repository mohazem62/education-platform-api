# الافتراضات والقرارات القابلة للتغيير

- لا توجد سياسة خصم تلقائي للإلغاء أو `NoShow`؛ الخصم يحدث عند تأكيد الحضور فقط.
- الدفعة ذات الحالة `Paid` تُعترف كإيراد حسب `PaidAt`. تكلفة المعلم تُعترف عند `Approved` أو `Paid` حسب `ApprovedAt`. المصروف يدخل عند `Approved`.
- العملة الافتراضية `EGP` قابلة للتهيئة، وكل دفعة تحتفظ بعملتها. لا يوجد تحويل عملات تلقائي.
- الفترة المالية يحددها المدير ولا يوجد إيقاع شهري مفروض.
- مجموع حصص الشركاء الفعالة يوم نهاية الفترة يجب أن يساوي 100%. النظام يرفض الإغلاق خلاف ذلك.
- لا توجد بوابة دفع أو مزود WhatsApp/Email مفترض. توجد واجهات توسعة فقط.
- لا يمكن للـ Moderator تعديل الأسعار أو تنفيذ عمليات مالية.
- التسليم بعد الموعد مسموح ويُعلّم `Late`؛ لا توجد عقوبة درجة تلقائية.
- الملفات تحفظ محليًا في التطوير خلف `IFileStorageService`، ويمكن استبدالها بتخزين سحابي.
- التصحيح المالي بعد الإغلاق يجب أن يكون بقيد Adjustment/Reversal جديد؛ لا تُعدّل الفترة المغلقة.
